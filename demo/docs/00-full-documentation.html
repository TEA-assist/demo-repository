What TEA is

TEA is an AI product finder for fashion retail. Shoppers describe what they want in natural language — English or Arabic, with typos, synonyms and paraphrases — and TEA returns ranked product cards with images, prices and store identity. Sellers manage stores and catalogs and get bilingual AI descriptions in one click. Admins curate the catalog, AI models, prompts and search quality.

  • For shoppers: no keyword gymnastics. Type "black evening dress" or "فستان سهرة أسود" and get relevant results, similar-product suggestions and a conversational assistant.
  • For store owners: create a store, add products with a guided wizard (names, attributes, variants, ≥3 images), then generate professional English + Arabic descriptions with one click.
  • For admins: full control — catalog data, AI chat, cron reports, conversations, LLM keys, 6 prompt templates, embedding status, search-evaluation metrics (MRR@10 / Recall@10), scraper headers.

Role summary (one paragraph each)

Admin

Logs in on asktea.ai with the admin account. Sees 8 dashboard tiles (Catalog Data, AI Chat, Cron Jobs, Conversations, LLM, Prompts, System, Scrapers). Browses the catalog taxonomy read-only, tests RAG chat with streaming product cards and a debug dialog, reviews AI-description and embedding cron reports (including destructive re-index with confirm), reads user conversations and feedback, generates/imports/judges search-eval queries and reads MRR@10/Recall@10 cards, manages LLM models and encrypted API keys, edits 6 prompt templates, toggles the description cron, tests embeddings, and pastes scraper headers. Full steps: Admin Guide →

Store Owner

Logs in (or admin uses Switch to Seller) and sees 4 nav items: Dashboard, Stores, Products, Profile. Creates/edits stores (name, phone, logo with crop, location, working hours), manages team members by phone/email with owner/manager roles, adds products through a 6-step wizard ending in AI description generation, and searches the product list with typo-tolerant fuzzy ranking. Full steps: Store Owner Guide →

Shopper (web + mobile)

No account needed to start: the public home has a hero, an anonymous chat box (ephemeral 10-minute session) and a random-products slider. Login via phone OTP or Google unlocks favorites and profile. On mobile: install the flavor APK, verify OTP (SMS autofill on Android), grant location/notifications, then browse the feed, open the chat drawer, view products and toggle favorites. How search and AI work (plain language)

  • Seller list search is typo-tolerant: exact-phrase matches rank first, then per-token trigram similarity across English and Arabic names. Under 3 characters it falls back to plain substring.
  • Shopper chat search is hybrid RAG: the query is embedded (dense vector) and tokenized (BM25 sparse vector), fused with RRF in Qdrant, filtered by color/material/category/brand/gender/size, then answered by the conversational LLM with streaming frames (assistant_start → text_chunk → product_cards → assistant_end).
  • Descriptions are LLM-generated bilingual JSON (en/ar) from 6 controllable prompt templates, with version history and restore.
  • Quality is measured on a 166-query golden set with MRR@10 and Recall@10 (overall + EN/AR), judged in the admin panel with limit:20 searches.
  • Deep dive: Technical Manual § AI pipeline and Presentation 03.

Security & operations (stakeholder summary)

  • Auth: phone OTP (10-min code) + Google Sign-In; web uses httpOnly cookies + CSRF, mobile uses Bearer tokens; refresh rotation with reuse detection; RBAC admin/seller.
  • Infra: 5 Swarm stacks on one overlay network; Caddy TLS via Cloudflare DNS-01; Postgres/Redis/RabbitMQ/MinIO/Qdrant; Grafana/Loki monitoring.
  • Known hardening note: loki:3100 has no auth and qdrant:6333 is host-published — remediation options are documented in the technical manual.
  • CI/CD: all repos build on self-hosted [self-hosted, tea-server] runners with quality gates → build → migrate → serialized Swarm deploy; /health exposes git_sha for demo verification.
