Admin Guide — asktea.ai

Role admin. Log in with the production admin account (dev admin restored to production). All pages live under /[locale]/admin/... — every URL starts with /en or /ar (locale prefix always, default ar with RTL). Switch between Admin and Seller views with the sidebar Switch to Seller button (persists tea_preferred_view — refresh the dashboard between roles to avoid stale caches).

1. Login

  1. Open https://asktea.ai/ar/login (or /en/login).
  2. Choose Phone → OTP (enter phone with country code, receive 6-digit code valid 10 min; dev bypass 1234 only when TWILIO_BYPASS=true) or Google Sign-In (code exchange via redirect_uri, one-time state).
  3. On success you land on /[locale]/admin. If login fails you stay on admin — sellers only ever see 4 nav items, admins see 11.

Guards: src/proxy.ts negotiates locale; dashboard layout sends unauthenticated users to /login and non-admins on /admin* to /seller.

2. Dashboard (/admin)

8 gradient tiles: Catalog Data · AI Chat · Cron Jobs · Conversations · LLM · Prompts · System · Scrapers. Each tile is a doorway to the sections below — start any admin tour here.

3. Catalog Data (/admin/data)

  1. Pick a product type from the selector (e.g. Fashion).
  2. Expand the category tree, then open attribute groups.
  3. Look for the is_search_affecting chip — those attributes are written into the AI embedding text, which is what makes "neckline", "sleeve", "occasion" etc. searchable without extra code.

Read-only browser. The live sellable catalog is the sellers' products.

4. AI Chat (/admin/product-search)

  1. Sidebar lists conversations (GET /chats). Click New chat (creates a conversation with create_new).
  2. Type a natural query — e.g. black evening dress or فستان سهرة أسود — and send.
  3. Watch streaming: text_chunk bubbles + product_cards grid. Open any card for the full product dialog.
  4. Click Debug on an assistant message to inspect the trace (rewritten query, filters, tool used, fallback path).
  5. Use similar-product chips to fire a similar_request follow-up turn.

Transport: wss://…/ws/chat/{id} with the token as subprotocol (no ?token=). Logic: useChat + useChatSocket.

5. Cron Reports (/admin/cron, /llm-product-description, /embeding-product)

  • Description cron: filter All / Pending / Generated, open a row for prompt + en/ar text + model + timestamp. Re-index button is destructive — confirm in the AlertDialog.
  • Embedding cron: per-model detail rows (embedding_status + model filters, active-model banner). Shows each product's per-model rows and embed-text preview.

6. Conversations (/admin/chats)

Read shoppers' chats + feedback. Columns include title + anonymous badge. Open a row for full message history (GET /admin/chats/{id}/messages) with ratings. There is no purge endpoint — history is retained.

7. Search Evaluation (/admin/search-eval) — the quality lab

  1. Generate: ask the LLM for 1–50 fresh queries (EN/AR checkboxes). They arrive as pending rows.
  2. Import: paste the inner array — jq '.queries' ~/Projects/TEA-assist/product-graph-api/scripts/seed_data/search_eval_golden.json | pbcopy — into Import. The page tolerates the wrapper object too, but the bare array is preferred. Expect 166 rows (124 EN / 42 AR).
  3. Judge: open a query → dialog auto-runs search with limit:20 → toggle relevant results → Save Judgments (or Skip).
  4. Read metrics: cards show MRR@10 + Recall@10 overall and per-locale EN/AR (cached 300s).

8. Settings

  • LLM (/admin/settings/llm): provider→model groups. Add / delete / toggle API keys (PATCH /:keyId/toggle), set the default model. Only models with active keys appear as options elsewhere.
  • Prompts: 6 editors — pre_prompt, ending_prompt, chat_assistant, parse_query, summarize, title. Single save.
  • System: toggle product_ai_generation_cron on/off.
  • AI Engine: provider/tunnel config + embedding test card (paste 1–1000 chars → full vector + copy button).
  • Scrapers (/admin/settings/scrapers): per-scraper status badges (error/ready), raw-header textarea draft, Save (PUT) / Clear (DELETE) with confirm. Tag ScraperHeaders.
  • Twilio/SMS (/admin/settings/twilio): connection card (masked SID, write-only token) + OTP whitelist table.
